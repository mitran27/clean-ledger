Proof-Carrying Agent

Every step of the investigation carries a proof: what each model was allowed to see, which tool calls it asked for, and that every action traces back to a signed step inside verified hardware.

What the numbers mean

  1. Pseudonymizer. Names become tokens before anything leaves. The map stays in a local vault.
  2. Cascade router. Jev scores every account in about 0.2 s. Only confident escalations reach the expensive TEE agent.
  3. Attestation sidecar. Verifies the hardware before sending, encrypts to the attested model key, verifies the signature after. Fails closed.
  4. Signed-tool gate. A tool runs only when the model response asking for it carries a valid TEE signature. Forged instructions can't act.
  5. Transcript chain. Each step's hashes link to the previous step, so any edit to the investigation is detectable.
  6. Private memory. Past cases are embedded encrypted and ranked locally. "Matches closed CASE-012."
  7. Case receipt. Proofs, the policy hash and the chain head, anchored on NEAR. An examiner can re-verify it offline.

Security extension

Six layers of defense, each built on a NEAR AI API

Each layer stops a different attack, so one failure does not expose the case. The reliability layer keeps the agent running without ever falling back to a weaker model.

Two-model rule

An account freeze is the one action that hurts a real customer if it is wrong. Before the outbox runs it, a second attested model from a different vendor reviews the same evidence independently. The freeze runs only if both agree; otherwise it goes back as a proposal.

Both models run in TEEs with their own attestation and signatures, so the second opinion is as private and verifiable as the first.

Attested failover pool

If the primary model fails, the sidecar moves to the next model only after attesting it. Every one of these returned hardware attestation and supports tool calling:

z-ai/glm-5.3-flash → z-ai/glm-5.3 → moonshotai/kimi-k3 → Qwen/Qwen3.8-27B → deepseek-ai/DeepSeek-V4.1-Flash-1017
